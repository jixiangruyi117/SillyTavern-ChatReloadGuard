# SillyTavern 聊天重载保护器

一个独立的 SillyTavern 用户级 UI 扩展，用于防止切换正则或含嵌入正则的预设时，聊天重载失败后把原聊天错误覆盖成只剩开场白。

本扩展不是聊天备份工具，也不会改变正则、预设或角色卡内容。它只在一次聊天重载期间，为当前聊天保留内存快照，并阻止已确认的危险覆盖链继续执行。

## 解决的问题

在已验证的 SillyTavern 1.18.0 流程中，切换正则或预设可能触发当前聊天重载。原始危险链是：

1. 重载开始后先清空页面内存中的当前聊天；
2. 再从服务器读取聊天；
3. 如果读取出现 HTTP 错误、网络错误或异常数据，后续流程仍可能把空聊天当成新聊天；
4. SillyTavern 创建角色开场白；
5. 只含开场白的聊天被保存，覆盖原聊天文件。

因此用户看到的不是“JSON 被普通配置覆盖”，而是原聊天记录消失，界面和保存结果都只剩开场白。本扩展针对的正是这条故障链。

## 保护范围

扩展保护以下场景：

- 切换正则触发当前聊天重载；
- 切换含嵌入正则的预设触发当前聊天重载；
- 当前聊天读取返回非成功 HTTP 状态；
- 当前聊天读取发生网络错误；
- 当前聊天读取返回畸形 JSON 或不符合聊天格式的数据；
- 当前聊天响应缺少应有的聊天头信息；
- 同一聊天的服务器结果相对重载前快照异常缩短；
- 重载期间尝试把同一聊天保存成比快照更短的内容；
- 重载回调抛出异常或结束后页面聊天仍异常缩短。

扩展不会处理：

- 多标签页或多设备同时编辑同一聊天产生的“最后写入覆盖”；
- 用户主动删除消息、主动新建聊天或主动切换到另一聊天；
- 已经在安装扩展之前被覆盖的聊天文件；
- 浏览器崩溃、刷新或关页之后的快照恢复，因为快照不写入磁盘；
- 未经审计的新 SillyTavern 版本。

## 工作原理

### 1. 启动时进行兼容检查

扩展读取 SillyTavern 版本并检查已导出的 `reloadChatMutex.callback`。只有版本和函数结构都符合当前审计结果时，才安装保护器。

如果检查失败：

- 未知版本：停止接管，提示当前版本不受支持；
- 重载函数结构已变化：停止接管，避免把旧修复强套到新实现上；
- 初始化异常：不修改重载回调，并显示错误状态。

### 2. 重载前创建内存快照

每次当前聊天重载前，扩展会复制：

- 当前聊天 ID；
- 当前群组 ID 或角色头像标识；
- 聊天元数据；
- 当前消息数组。

这是脱离原数组的内存副本。快照不会写入扩展设置、浏览器存储、日志或服务器。

### 3. 仅在本次重载中保护当前聊天请求

扩展临时包装全局 `fetch`，但匹配范围同时受以下条件限制：

- 请求发生在受保护的这一次重载回调内；
- 请求路径属于 SillyTavern 的角色聊天或群聊读取/保存接口；
- 请求标识与快照中的当前角色或当前群聊完全匹配。

不同聊天的请求、其他接口请求和其他扩展的无关请求继续原样透传。正常响应也原样交给 SillyTavern，不会被重写。

### 4. 读取异常时返回快照

当同一聊天的读取结果不安全时，扩展向本次 SillyTavern 重载流程返回快照格式的响应，使后续流程重新得到原聊天，而不是把空数组初始化成开场白。

当前代码识别的保护原因包括：

| 原因 | 含义 |
| --- | --- |
| `http-<状态码>` | 当前聊天读取返回非成功 HTTP 状态 |
| `network-error` | 请求抛出网络异常 |
| `invalid-json` | 响应无法解析为 JSON |
| `invalid-load-response` | 响应结构不是有效聊天数组 |
| `missing-chat-header` | 响应缺少聊天元数据头 |
| `unexpected-chat-shrink` | 同一聊天的返回消息数异常少于快照 |
| `integrity-conflict` | 返回内容与快照存在完整性冲突 |

### 5. 阻止同一聊天的危险保存

如果故障链继续尝试把同一聊天保存成比快照更短的内容，扩展会拦截该保存，并让页面恢复快照。压缩请求体也在现有回归测试覆盖范围内。

只要保存目标是另一聊天，请求就会透传。这一行为有专门的兼容回归测试，避免误拦其他扩展在同一时段对不同聊天的操作。

### 6. 无论成功或失败都撤销临时接管

原始重载回调成功、失败或抛出异常后，扩展都会在 `finally` 阶段恢复原始 `fetch`。保护器卸载时也会恢复原始 mutex 回调，不长期占用全局请求入口。

## 为什么尽量不影响 SillyTavern 和其他扩展

- 不修改 SillyTavern 安装目录或核心源码；
- 不修改正则、预设、角色卡和聊天消息的正常格式；
- 只在一次当前聊天重载的时间窗口内临时工作；
- 同时校验接口路径和聊天身份，不按“所有聊天请求”做宽泛拦截；
- 正常读取、正常保存和不同聊天请求全部原样透传；
- 结束后恢复原始 `fetch` 和原始调用结果；
- 未知版本或未知内部结构采用不接管策略；
- 已有测试会检查不同聊天的插件保存请求不会被阻止。

这些限制用于降低兼容风险，但不能等同于对所有未来 SillyTavern 版本和所有第三方扩展作无限保证。升级 SillyTavern 后应先查看扩展状态并完成一次安全验证。

## 安装

### 从 GitHub 安装

1. 打开 SillyTavern 的“扩展”页面；
2. 选择“安装扩展”；
3. 粘贴以下仓库地址：

   ```text
   https://github.com/jixiangruyi117/SillyTavern-ChatReloadGuard
   ```

4. 完成安装后刷新页面或重启 SillyTavern；
5. 在扩展设置中展开“聊天重载保护器”；
6. 确认状态为“保护中”。

酒馆更新通常不会覆盖用户级第三方扩展。扩展更新后仍会重新执行版本和内部接口检查。

### 本地开发安装

把仓库复制或链接到当前 SillyTavern 用户的扩展目录：

```text
data/<用户>/extensions/SillyTavern-ChatReloadGuard
```

刷新页面后，在扩展设置中确认加载状态。不要为了安装本扩展直接修改 `public/script.js` 或其他 SillyTavern 核心文件。

## 设置状态说明

| 状态 | 含义 |
| --- | --- |
| 检查中 | 正在读取版本并检查内部结构 |
| 保护中 | 兼容检查通过，重载保护已接管 |
| 已阻止一次危险重载 | 本次重载发现异常并使用了快照或阻止了危险保存 |
| 未启用 | 当前版本不在已审计支持范围内 |
| 未接管 | 内部结构不匹配，可能已被上游修改或修复 |
| 启用失败 | 初始化失败，保护未启用 |

如果不是“保护中”，不要假定扩展仍在后台保护聊天。应先保留聊天备份，再检查版本、控制台错误和扩展更新。

## 已经丢失聊天时怎么办

本扩展用于阻止之后发生的同类覆盖，不能从内存中恢复安装前已经丢失的记录。遇到聊天只剩开场白时：

1. 暂停继续在该聊天中发送消息，避免产生更多保存；
2. 先复制整个当前用户数据目录作为现场备份；
3. 检查该用户目录下 SillyTavern 的聊天备份文件；
4. 选择事故发生前的备份，在副本中核对内容后再恢复；
5. 恢复前保留当前文件，不要直接覆盖唯一副本。

备份目录和保留数量取决于 SillyTavern 配置。本扩展本身不创建磁盘备份，也不自动替用户选择或覆盖恢复文件。

## 移动端软键盘高度修复与只读诊断

扩展设置中提供两个默认关闭、彼此独立的选项：

- **修复移动端软键盘高度残留**：输入框聚焦前保存页面稳定高度。软键盘打开时使用真实可见高度，失焦时立即恢复键盘前高度，不等待某些 Android 浏览器迟到的视口更新。
- **记录移动端键盘诊断（只读）**：仅记录从文本输入框或可编辑区域聚焦，到失焦后 600ms 的一次完整过程，最多在当前页面内存保存 120 条事件；失焦当刻停止接收新的 resize 和长任务，只保留已排定的 100/300/600ms 取证点。完整布局读取只发生在锚点及固定定时点，频繁 resize 会合并为轻量来源/尺寸记录，避免诊断本身制造卡顿。点击“复制精简诊断”时自动提取最近一次过程，最多导出 18 个关键事件，并把重复布局样式压缩成一份摘要。报告不包含聊天正文、输入内容、账号、凭证或网络请求。

建议测试时同时开启两项，依次执行“点输入框 → 等键盘完全打开 → 收起键盘 → 等黑块出现或页面恢复”，然后点击“复制精简诊断”。如果修复导致新的定位异常，先关闭修复开关；只读诊断可以继续开启以保留证据。

此功能针对已审计的 SillyTavern 1.18.0 移动布局链，真机复验完成前不声明所有 Android 浏览器均已修复。

真实 SillyTavern 验证应使用可丢弃的测试聊天，不要拿唯一的重要聊天做故障注入。至少确认：

1. 设置页状态为“保护中”；
2. 正常切换正则和预设不会改变消息数与内容；
3. 模拟当前聊天读取失败后，原聊天仍在，且没有保存只含开场白的结果；
4. 取消故障后可以正常继续聊天与保存；
5. 其他已安装扩展的相关操作没有新增报错。

## 二次开发指南

如果原项目后续不再维护，其他开发者可以在遵守 `PolyForm-Noncommercial-1.0.0`、且用途属于非商业范围的前提下，fork 仓库继续研究和优化。请先阅读本节和源码，不要只根据扩展名称重写一套宽泛的聊天拦截器。

### 开始前

1. fork 仓库并从独立分支开发，保留可回退的 Git 提交；
2. 阅读 `WORK_LOG.md`，确认原始故障链；
3. 阅读 `modules/ChatReloadGuardCore.js` 和现有测试；
4. 运行 `npm run check`，保证修改前基线通过；
5. 使用与目标版本一致的 SillyTavern 源码重新定位真实重载流程；
6. 先写能复现问题的回归测试，再改保护逻辑。

### 必须保留的安全边界

二改时请不要破坏以下约束：

1. **精确识别当前聊天。** 不能仅凭 URL 中出现 `chat` 或消息数量变少就拦截；角色聊天需核对角色标识，群聊需核对群组与聊天 ID。
2. **只保护单次重载窗口。** 临时 `fetch` 必须在 `finally` 中恢复，不能安装永久、无范围的全局网络代理。
3. **无关请求必须透传。** 不同聊天、其他接口和其他扩展请求不能因为保护器启用而被统一阻止。
4. **正常结果不能被改写。** 有效读取和有效保存应保留原始响应和原始 SillyTavern 行为。
5. **未知版本默认不接管。** 不要把版本判断改成通配符，也不要仅为消除“不支持”提示就加入新版本号。
6. **先审计内部结构再声明支持。** 新版本必须重新核对清空、读取、异常处理、初始化和保存的完整调用链。
7. **快照默认只留内存。** 不要把聊天内容写入日志、设置、遥测或远程服务。若要做持久化恢复，应作为明确的新功能设计隐私、加密、保留和清理策略。
8. **保留压缩请求兼容。** SillyTavern 可能发送 gzip 请求体；修改保存检查时必须继续测试压缩与非压缩两条路径。
9. **不要修改酒馆核心文件。** 继续使用用户级扩展边界，避免把修复写进本地 `public/script.js` 后随升级丢失。
10. **不要用开场白数量作唯一判断。** 正常聊天本来就可能只有一条消息；保护依据必须结合重载前快照、目标聊天和当前调用窗口。

### 适配新的 SillyTavern 版本

增加新版本支持时，建议按以下顺序执行：

1. 在目标 SillyTavern 源码中定位正则/预设切换如何触发聊天重载；
2. 核对是否仍存在“先清空、后读取、读取失败后初始化并保存”的危险链；
3. 核对读取和保存接口、请求字段、群聊字段及压缩方式；
4. 更新兼容检查，让它识别经过审计的实际函数结构；
5. 只在证据充分后更新 `SUPPORTED_VERSIONS`；
6. 增加该版本的失败链、正常链、群聊链和跨聊天兼容测试；
7. 在可丢弃数据上完成真实页面验证；
8. 在 README、`CHANGELOG.md` 和版本清单中写明验证基线。

如果新版本已经在上游彻底消除了危险链，正确做法可能是保持“未接管”，而不是强行让扩展显示“保护中”。

### 修改接口匹配时

若 SillyTavern 更换聊天 API：

- 以目标版本的真实请求为准更新角色聊天和群聊路径；
- 同时更新读取与保存匹配，不要只改其中一侧；
- 保留请求体解析失败时的安全行为；
- 添加同一接口下“当前聊天应保护、另一聊天应透传”的成对测试；
- 检查响应头和聊天数据结构，不要只验证 HTTP 200。

### 修改 UI 时

- 设置面板只展示保护状态、原因和必要提示，不展示聊天正文；
- 不要把“扩展已加载”误写成“保护已启用”；
- “不支持”“未接管”“错误”必须保持可见，不能为了界面简洁而静默失败；
- 保持移动端设置页可读，不依赖固定宽度；
- UI 文案变化后仍要与真实运行状态一一对应。

## 隐私与安全

- 扩展不调用自有远程 API；
- 扩展不需要账号、令牌或聊天数据库访问凭据；
- 聊天快照只存在当前页面内存中；
- 设置提示使用消息数量和保护原因，不应输出聊天正文；
- 页面刷新、关闭或崩溃后，内存快照随之消失。

## 提交问题时请提供

请在仓库的 [GitHub Issues](https://github.com/jixiangruyi117/SillyTavern-ChatReloadGuard/issues) 中新建问题。文档表述不准确、功能异常和兼容性问题都可以通过这里反馈。

- SillyTavern 完整版本号和修订号；
- 本扩展版本；
- 设置页显示的状态；
- 触发步骤，例如切换了正则还是预设；
- 浏览器控制台中与本扩展有关的错误和 HTTP 状态；
- 是否为角色聊天或群聊；
- 是否安装了会参与聊天读取、保存或预设切换的其他扩展。

请删除聊天正文、角色私密信息、服务器地址、令牌和其他凭据后再提交日志或截图。

## 已知边界

- 多标签页或多设备的并发写入不在本扩展的保护范围；
- 服务器返回同一聊天的较短内容时，扩展会优先保留页面快照并提示检查备份，不会自动用较短结果回写服务器；
- 未验证的新 SillyTavern 版本不会自动接管；
- 内存快照不是持久备份，不能替代 SillyTavern 自身备份和用户的数据备份策略。
